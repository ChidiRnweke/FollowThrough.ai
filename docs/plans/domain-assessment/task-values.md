# Task model declaration review

This is a current declaration review of src/lib/models/todos/index.ts, after the task ownership,
promise owner/date, completion-state and source-anchor slices. It is not a replacement for the
historical source inventory, and it does not certify every task workflow. Implementations remain
on the open dependent stack.

| Declarations                                                                                                        | Disposition and reason                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Brand; UserId, ProjectId, NoteId, TodoId, SourceAnchorId, ProvenanceId, DateTime, LocalDate                         | Retain identity and value types. Request, provider and storage boundaries parse them; domain rules do not parse external values. LocalDate is a calendar date, distinct from a timestamp.                                                                                                                                                                    |
| TextSelection                                                                                                       | Retain the complete selected-passage input shape. Note ownership, revision and text agreement are decided by SelectionOrigins. The task model does not own those checks.                                                                                                                                                                                     |
| TodoStatus, TodoResponsibility, TodoPriority, PromiseStrength                                                       | Retain product vocabularies. Cancelled is a valid task state even though the default board and board export omit it. Strength describes extracted commitment wording, not completion or priority.                                                                                                                                                            |
| DEFAULT_PROMISE_MODEL; PromiseModelContext                                                                          | Retain configuration data and the resolved model/request-time pair. Capability construction chooses the model; durable execution freezes request context. The model contains no provider calls or fallback algorithm.                                                                                                                                        |
| promiseExtractionSchema; PromiseCandidate                                                                           | Retain the provider response schema and mapped candidate value. The schema validates calendar dates and confidence. Owner identity, original deadline wording and a resolved date are independent facts; unknown owner/date values remain absent. PRs #204 and #205 preserve the owner and validate the provider date.                                       |
| TodoFields; Todo                                                                                                    | Retain the resolved commitment. Completion state now requires a timestamp exactly for done tasks (#206). Deletion preserves history. Priority, category, description, deadline and provenance can each be absent independently. A linked note is a user-selected display source; an anchor is the extraction origin. Those facts can exist separately.       |
| CreateTodoInput                                                                                                     | Retain a request value with optional identity/status and independently supplied context. The controller resolves identity, actor and time; the shared creation rule resolves title, status, completion and responsibility. TodoCreator receives the resolved task.                                                                                           |
| batchProjectId, batchLocalDate, createTodoBatchSchema; CreateTodoBatchInput, CreateTodoBatchOutput, TodoBatchLookup | Retain batch boundary values and durable receipt outcomes. Missing, reused-with-different-input and saved are distinct states. The receipt service rejects changed input; the controller owns atomic creation and preserves input order. The model does not perform retries or persistence.                                                                  |
| ExtractPromisesInput, StartExtractPromisesInput, startExtractPromisesSchema, ExtractPromisesOutput                  | Retain selection requests, the durable request identity and typed results. The controller binds the generic proposal result to TodoSuggestion, owns approval/automatic acceptance and returns the resulting proposal state. Selection/provider work and durable settlement stay outside the model.                                                           |
| NoteRef, TodoView, GetTodoViewInput, TodoContext                                                                    | Retain explicit task display values and read facts. The shared view rule gives the selected linked note precedence while retaining the extraction origin. Browser records can arrive independently, so an anchor can be available before its note. A missing note does not invent a title. The canonical SourceAnchor type now belongs to provenance (#207). |
| TodoListFilter, ListTodosOutput                                                                                     | Retain narrow query values and the view result. Actor/project/deletion filtering belongs to repositories or the account-scoped browser projection. URL parsing belongs to the client boundary. Presentation title search and table ordering stay in the components.                                                                                          |
| UpdateTodoInput, UpdateTodoOutput                                                                                   | Retain partial command intent separately from resolved state. Undefined means no requested change; null clears supported fields. Controllers lock the task and apply shared rules once. The output carries the saved task and its view. Explicit linked-note assignment validation is separate from retaining an existing archived link (#209).              |
| BoardMarkdownOptions, BoardPdfExportResult                                                                          | Retain caller-supplied export context and ephemeral output. Date generation, column policy, Markdown rendering, PDF preparation and download I/O remain outside the model. Optional project names are presentation context, not missing task ownership.                                                                                                      |

The independent-field checks above include storage lifecycle changes: deleting an origin can clear
its anchor without clearing all provenance, and clearing a selected linked note does not remove the
extraction origin. Request optionality is not copied into the resolved completion state. No new model
service, persistence wrapper or test-only constructor is needed for the retained declarations.

## Read contracts

Current call-site inspection found no consumers of DueTodoFinder, TodoSourceFinder or
TodoCatalog.findDue. They are retired rather than retained as duplicate paths. The unused due helper
also cast an arbitrary string to LocalDate. Today already uses TodoLister.list with its parsed local
date. TodoContextReader supplies origin and link facts to the shared view rule. WaitingOnFinder is
retained: Workspace.getTodayView actually calls it.

Task creation/edit, batch receipt, extraction, source reading, list/count, board export and workspace
parity tests remain with those behaviors. No test is added to prove that an unused method was deleted.
Workflow coverage is tracked separately in [the read disposition](task-reads.md) and the workflow ledger.
