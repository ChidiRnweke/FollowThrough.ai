FollowThrough has two kinds of search, and neither is a screen you open: there's no search box in the app. **Knowledge search** is semantic search over your own material (notes, attachments, diagrams, and the memory you've shared with agents), and it powers both the agent's `search` tool and the inline "find related" suggestions in the editor. **Web search** is a tool the agent calls during a run when it needs current or external information, and you choose the engine and the result caps.

## Let your content become searchable

You don't have to do anything: saving a note, importing a document, drawing a diagram, or letting the agent remember a fact puts that content into the index automatically. Archive or empty a source and it drops out of the index immediately, so the agent never surfaces something you've already put away.

The retrieval pipeline works like this:

A few properties worth knowing:

- **Edits are cheap.** Chunks are keyed by content hash, so editing a note only re-embeds the chunks that actually changed. The rest keep their vectors.
- **Very large attachments are indexed head-first.** The opening portion (up to 50 chunks) is searchable; the remainder is recorded as truncated rather than embedded.
- **Only shared project memory is indexed.** A memory entry enters the index only if it belongs to a project and you've marked it as shared with agents. Profile memory (what the agent knows about you across everything) is injected into the agent's context directly and never goes through search. Deleted facts never appear in results.
- **Retrieval is two-stage.** The vector search casts a wide net (at least 40 candidates), then a reranker shrinks that to the final few, so recall comes cheap and precision comes second.

To see this pipeline in the editor, select text in a note: FollowThrough searches within the project for passages that mention, contradict, or record a prior decision about the selection, and surfaces them as "find related" suggestions. The agent's `search` tool runs the same pipeline and returns a handful of excerpts (eight by default, each capped at 700 characters) with a relevance score. It searches when workspace evidence could improve the answer, searches again with a sharper query when the first results reveal a lead or a gap, and restricts the search to one project when your request is clearly scoped to it.

## Tune web search

Web search is a tool attached to every agent conversation. The model calls it when a question needs current or external information (documentation, prices, news) rather than anything you've saved. It runs through the deployment's OpenRouter connection, with Exa as the default engine; without that connection the agent works from your knowledge base alone.

Open **Settings > Agents** to set three things, each of which you can leave unset to follow the deployment default:

- **Web search engine:** `auto`, `native`, `exa`, `firecrawl`, `parallel`, or `perplexity`. Choose `auto` to let the model pick per query.
- **Results per search:** caps a single search, between 1 and 50. The deployment default is 20.
- **Total results:** caps what a run may pull across repeated searches, between 1 and 100. The deployment default is 40.

You can also change these mid-conversation: the agent has tools for reading and updating its own settings, so asking "use fewer web results" works. Clearing a setting returns it to the deployment default rather than to zero.
