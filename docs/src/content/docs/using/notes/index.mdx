Open a note and start typing. A note is a rich-text Markdown document inside a project, edited in a vendored TipTap editor: it autosaves two seconds after you stop typing, saves to your device first, and syncs when it can. Select any text to reach AI actions (ask about it, extract promises, find related notes, propose references, generate a diagram), and Mermaid diagrams render inline and convert to draw.io.

## Edit the note

The page is one continuous writing surface with a quiet utility row above it: breadcrumb, save status, and actions. Click the title in the breadcrumb to edit it in place; press Enter to commit and drop the caret into the body, or Escape to revert. An untitled note can't save; the row says "Add a title to save" until it has one.

A save never changes a note's project or turns it into a folder (moving is its own action), and an archived note stays read-only until you unarchive it.

## Watch the save status

You never have to press save for routine editing: the note autosaves two seconds after you stop typing, and Cmd/Ctrl+S saves immediately. Every save lands on your device first, then syncs to the server. Read the status in the utility row to know which state you're in:

- **Saved, _time_:** device and server agree; the timestamp says how long ago.
- **Syncing:** a save is in flight.
- **Saved on device, retry sync:** you're offline or the server was unreachable. The note is safe locally and syncs on its own once the connection returns.
- **Couldn't save, retry:** the last sync failed. Hover the status for the reason.
- **Review conflict:** the note changed elsewhere since you started editing.
- **Unpublished changes:** saved, but newer than the last published version.

If you hit a **Review conflict**, a dialog opens that diffs both versions against the version you both started from. Choose **Keep mine** to rebase your text on top of the latest version and re-sync, **Use latest** to discard your local edits, or **Review later** to leave the note conflicted until you decide. Whichever you pick, you keep a complete document; there's no line-by-line merge. (A stale save whose remote content is identical to yours still resolves to Saved, so retrying a save that actually landed never shows a false conflict.)

Sync your note before moving, archiving, publishing, or running any AI selection action; if it's not synced, you'll be told to sync first and nothing else happens. If the editor itself fails to render a note, the page says so and offers a retry; nothing is written while the editor is down, so the saved note on the server stays untouched.

## Run an AI action on a selection

Select text and choose from the bubble menu: **Ask about this**, **Extract promises**, **Find related**, **Reference**, **Diagram**, plus any skills you have. While one runs, the menu becomes a single status line and the selection keeps its highlight until the result lands.

<Screenshot id="in-editor-ai" alt="The bubble menu over a text selection with AI actions" />

Every action is a proposal, not a silent edit. Extract promises puts todo suggestions in the Suggestions panel, Find related proposes backlinks, and Reference proposes ranked references. Nothing lands without your accept.

A few other editing shortcuts worth knowing:

- Type `@` at the start of a word to link another note in the same project. The link lands as the note's title and opens without a page reload.
- Paste or drop an image to upload it as a note attachment.
- Right-click the editor for raw and formatted copy and paste.
- Turn on inline suggestions in settings to see suggested continuations (ghost text) as you write; a suggestion that can't answer just stays silent.

Hover a backlink chip (the compact row between the utility row and the document) to see the relationship kind (mentions, elaborates, contradicts, prior decision), its justification, and when it was made. A `contradicts` chip is tinted so it reads as a warning, not a link.

## Turn a selection into a diagram

Select text and choose **Diagram** to generate a Mermaid diagram and insert it where the cursor was (undo with Ctrl+Z). A Mermaid block renders inline as you type and opens into an editor with its own zoomable preview, where you can revise it by instruction or convert it to draw.io.

<Screenshot id="diagram-render" alt="A Mermaid diagram rendered inline in a note" />

A conversion opens as a draft in a dialog: accept it to insert a draw.io preview right after the Mermaid block, or dismiss it to leave the block untouched. Accepted draw.io diagrams open in a focused editor with an explicit Save.

## Open two notes side by side

Drag a note from the sidebar or a workbench tab onto the open note to open it beside the current one. The split lives in the URL (`?split=`), so it survives a reload or a copied link, and it remembers the divider ratio you set. Each pane scrolls independently and keeps its own save status. On a narrow window only one pane shows at a time, with a switcher; the split itself isn't discarded. While a split is open, use **Compare** in the primary pane's note menu to ask the agent about both notes.

## Publish a version

Choose **Publish** from the note menu to record the current state as the note's published version, a versioned snapshot. Choose **Discard changes** to restore the last published one. With unpublished changes present, pressing Cmd/Ctrl+S twice in quick succession publishes instead of saving. The same menu pins a note to the sidebar, moves it between folders, exports it as PDF or DOCX, and archives it. (A folder still holding notes can't be archived.)

## Import a Markdown vault

Open a project page's menu and choose **Import an existing project...** to upload a `.zip` of Markdown files. FollowThrough recreates it as notes, keeping the folder structure: each note takes its title from its file name, `[[wiki links]]` between imported notes become real note links, and YAML frontmatter is stripped (the closing report names any keys that weren't imported).

The archive can hold up to 25 MB and 2,000 files, each file up to 1 MB and at most 8 folders deep; `.obsidian/`, `.git/`, `.trash/`, `__MACOSX/`, and other dotfile paths are ignored. An import isn't all-or-nothing: readable notes import even when sibling files fail, and the report lists every failed and skipped file with its reason. Two notes with the same name in one folder never merge; the later one gets a ` (2)` suffix.
