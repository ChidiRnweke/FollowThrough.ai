Create a project to give the agent a complete, bounded picture of one body of work. A project is the unit everything hangs off: notes and folders form its document tree, and around them sit the spaces the agent reads from and produces into (memory, attachments, todos, and artifacts). Skills, reusable instruction sets for the agent, are stored in the project too. If you never create one, FollowThrough provisions a default project called **General** and puts everything there.

The split that matters is direction. **Memory and attachments are what the agent works from**, the material it reasons over when it answers, while **todos and artifacts are what the project produces**: commitments extracted from your notes, and deliverables the agent generated with your approval. Notes sit in the middle as the shared surface you and the agent both write on. This scoping isn't cosmetic: when the agent searches your knowledge base, grounds an answer, or lists what it can act on, a project boundary is usually the filter, and you can always ask it to work within one project explicitly.

## Read the overview

Open a project to land on its overview, which groups the spaces by that same direction: **Produced here** (Todos and Artifacts) and **What the agent works from** (Memory and Attachments). A populated space states what it holds (`3 open, 1 overdue` on Todos, `2 files grounding the agent` on Attachments); an empty space shows a rotating tip about what it's for instead of a zero.

<Screenshot id="project-context" alt="A project overview with its spaces and document tree." />

Below the spaces sits the document tree. Notes carry their relative last-edited time, and documents still named `Untitled` are counted beside the heading as a standing invitation to name them. If a project is empty, create the first note or import an existing project as a zip of Markdown files, structure and all; the closing report separates what was imported from what was skipped and what failed, so a partial import stays visible instead of silent.

## Organize notes and folders

The tree holds notes and folders. Folders have no page of their own; they exist to group notes and expand in place. Drag entries in the sidebar tree to reorder or re-file them. The move is validated: the target must be a folder, and an entry can't move under itself or one of its own descendants.

## Choose project memory or profile memory

Memory exists at two levels. **Project memory** is scoped to the project (decisions, constraints, and context that only make sense inside this body of work), while **profile memory** is what the agent knows about you across everything and lives on the profile page; a suggested memory that isn't tied to any project surfaces there instead. Project memory you share with agents becomes searchable and is injected when the agent works in that project; profile memory is injected into the agent's context directly, everywhere. See [Memory](/FollowThrough.ai/using/memory/) for the sharing and approval flow.

## Create, rename, or archive a project

- Choose the `+` beside the Projects group in the sidebar to **create a project**.
- Use the project page header to **add a note or folder**.
- Open the project actions menu (the `...` in the header) to **rename, set export defaults, import a Markdown archive, or archive**.
- Use the hover menu on a document's row in the documents list to **rename or archive that document**.

Names are required and trimmed, and two active projects can't share a name (casing aside); the save fails with that explanation rather than overwriting. Archiving frees a project's name for reuse, sets a timestamp, and takes the project out of every default view: it leaves the sidebar, the workspace, and the name-uniqueness check, and its documents stop appearing in search. There's no delete, and no archived-projects list in the UI to restore from, so treat archive as final. Documents inside a project work the same way: archive, not delete.
