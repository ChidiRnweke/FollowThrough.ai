This guide follows one project, a docs site relaunch, from a brief to a working plan. You give the
project its context. The agent reads that context and does work in the project. You edit the result
yourself, and the agent builds on your edits. Every screen below is the real app, working on the same
data.

<Steps>

1. ### Start with what you already have

   Select **+** next to **Projects** in the sidebar and name the project. On the project page:
   - Select **New note** and write what you know: scope, decisions, owners, and a schedule.
   - Open **Attachments** and add the files you have, such as the brief as a PDF.
   - Open **Memory** and add the facts that must hold, such as "The launch needs legal approval and
     a completed QA pass."
   - Open **Todos** and add the work that is already known.

   <Screenshot
   	id="walkthrough-01-context"
   	alt="The Docs site relaunch project page: a planning note, two todos, two memories the agent can use, and one attached file."
   	caption="The project holds the note, the brief, the memories, and the todos. They belong to the project, not to one conversation."
   />

2. ### Ask for work, not answers

   Open a note and select the chat icon in the left rail. On a wide screen, the chat opens beside the
   note, and the open note is already in its context. Ask for the work you want done:

   > Read the launch brief and these planning notes. Write a release plan note, add the outstanding
   > launch tasks to the board, and export the release plan as a Word brief for the team.

   In approval mode, the agent stops before each change and shows an **Approve** and **Reject**
   card. The chat lists every action it took, including any that failed.

   <Screenshot
   	id="walkthrough-02-agent-acts"
   	alt="The new Release plan note open beside the chat. The chat lists each action: the note and seven todos created, a Word export, and a proposed memory."
   	caption="From one request, the agent wrote a release plan, added seven todos with owners and dates, and exported a Word brief."
   />

3. ### Keep working yourself

   The agent's note is your note too. Edit it like any other note. In this example, QA changes from
   3 to 5 days, and a new line makes a promise: "I will verify every redirect on staging before
   Thursday."

   Select that sentence and choose **Extract promises** in the toolbar above it. The todo appears
   under the sentence as a proposal, with the owner and a due date worked out from the text. Select
   **Accept** to add it to the board. The todo stays linked to the sentence it came from.

   <Screenshot
   	id="walkthrough-03-extract-promise"
   	alt="A highlighted sentence, 'I will verify every redirect on staging before Thursday', with the selection toolbar above it and a proposed todo below it, due 15 October, with Accept and Dismiss buttons."
   	caption="Highlight a commitment and extract it. The proposed todo appears in place until you accept or dismiss it."
   />

4. ### Build on what changed

   Ask the agent for something new that uses the edited note:

   > Build an interactive critical-path simulator for this launch plan. Use the stages and durations
   > in this note. Let me change each stage with a slider and show which workstream sets the launch
   > date. Embed it in this note.

   The agent reads the note as it is now, so it uses 5 days for QA. It proposes a
   [widget](/FollowThrough.ai/using/widgets/) and shows a preview in the chat. Nothing goes into the
   note until you approve it.

   <Screenshot
   	id="walkthrough-04-widget-proposal"
   	alt="The chat shows a proposed Critical-Path Simulator widget: the development stream ends on day 16, content on day 9, and sliders hold each stage's duration, with QA at 5 days."
   	caption="The proposal computes from the edited plan: development takes 16 days and sets the launch date."
   />

5. ### The work stays

   After you approve, the widget is part of the note. Move a slider and the results change at once.
   Here, Legal review moves to 12 days, so the content stream takes 17 days and becomes the critical
   path.

   <Screenshot
   	id="walkthrough-05-widget-result"
   	alt="The simulator embedded in the Release plan note. Legal review is set to 12 days, the content stream now ends on day 17, and the critical path reads Content stream."
   	caption="The release plan, the todos, the widget, and the Word brief are now part of the project."
   />

</Steps>

<Aside type="tip">
	Everything you keep becomes context for the next conversation. The next time you ask about this
	project, the agent starts from the plan, the todos, the widget, and the decisions in memory.
</Aside>
