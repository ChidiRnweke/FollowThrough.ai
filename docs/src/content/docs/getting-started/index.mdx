## TL;DR

FollowThrough is an agent-native note editor you never have to brief. You think in notes; the agent extracts the commitments and context, you triage on Today, the agent acts with your approval, and the work becomes artifacts and deliverables.

One project, one note, all the way to a finished output — about ten minutes, start to finish.

<Steps>

1. ### Create a project

   Open the sidebar and create a project. A project is the unit of work that pulls everything else together: its notes, board, memory, skills, and outputs all live under it. Give it a name that tells you — and a future agent — what it is about.

   <Screenshot id="project-context" alt="A project overview: what the project produced above, what the agent works from below." />

2. ### Write a note

   Create a note inside the project and write a few paragraphs. Notes are Markdown, so rough thinking, meeting notes, plans, and drafts all belong here. This is the material every later step works from.

   <Screenshot id="note-view" alt="A note open in the editor: one continuous writing surface, title in the breadcrumb." />

3. ### Turn thinking into action

   Select a sentence or paragraph that contains a commitment — something you promised to do, or asked someone else to do. Run **Extract promises**. FollowThrough finds the commitments, and each one becomes a reviewable todo suggestion.

   Look at the suggestions pane: each suggestion carries a confidence score and traces back to the exact selection it came from. Accept the ones that are real. Accepted todos appear on your board.

   <Screenshot id="in-editor-ai" alt="Extracted promises anchored in the note text, with reviewable suggestions alongside." />

4. ### Ask the agent

   Open the chat in the project and ask a question, for example: *"Summarize what still needs doing this week."* The agent reads the project's notes, board, and memory rather than asking you to explain the context again.

   If the agent wants to make a change — update the project memory, edit a note, create a todo — it proposes the change first. Accept or reject it in the approval card. Agents propose; you accept.

   <Screenshot id="in-editor-chat" alt="The project chat open beside a note: the agent answers from the project's own context." />

5. ### Review what the agent learned

   Each project has its own memory: the facts, decisions, and constraints an agent needs to help without being re-briefed. When the agent proposes a memory update, review it. Anything you reject never becomes part of the project's durable understanding.

6. ### Finish something

   When your project has enough material, produce an output that can leave the app. Select a note and generate a document from a template, turn a paragraph into a diagram, or draft a brief. The result is an artifact of the project — connected to the source it came from, not an isolated generation.

   <Screenshot id="diagram-render" alt="A Mermaid diagram rendered inline in a note, with a draw.io conversion available." />

</Steps>

<Aside type="note">

Throughout, work moves one direction: notes become actions, actions become artifacts, artifacts become finished work. If a step ever feels like a dead end, it is probably being done in the wrong order — the loop always starts from a note.

</Aside>
