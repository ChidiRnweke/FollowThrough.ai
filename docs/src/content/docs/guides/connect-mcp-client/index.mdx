Open **Settings → MCP access** to run your workspace headless from an external MCP client. The same tool catalog the in-app agent uses (every controller-backed capability, classified as a read, a proposal, or a mutation) is reachable from the client you connect, gated by whichever tools you've left enabled and the scope of the token you mint.

## Mint a token

1. In **Settings → MCP access**, name the token after the client you're about to paste it into (`Claude Desktop`, for example), so you know what you're revoking later.
2. Choose a scope: **Read only** restricts the client to read tools (search, list todos, read memory) and nothing else; **Full access** allows proposals and mutations too, gated the same way the in-app agent's execution mode gates them.
3. Choose **Create token**. The plaintext token is shown exactly once, in a banner that says so; copy it now. It's stored as a hash, so if you lose it, revoke it and mint another rather than trying to recover it.

## Point your client at the endpoint

Copy the **Endpoint** field on the same page (`/mcp`) and add it to your client's MCP server configuration along with the token as a Bearer credential. In Claude Desktop, for example, this goes in the server's connection settings as an `Authorization: Bearer <token>` header. The connection is stateless JSON-RPC, so there's no separate session to establish beyond that header.

## What the client can do

Once connected, the client sees the first-class tools immediately. Call `search_tools` for anything else; every match becomes a real top-level tool with the returned flat input schema. A read-scoped token never sees proposal or mutation tools, and a full-access token still respects your workspace tool selection.

## Revoke access

Open **Settings → MCP access** and choose **Revoke** on any token's row. Revocation is immediate: the next request with that token fails with a `401`, and there's no grace period.
