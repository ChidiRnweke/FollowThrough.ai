Open **Settings → MCP access** to run your workspace headless from an external MCP client. The same tool catalog the in-app agent uses (every controller-backed capability, classified as a read, a proposal, or a mutation) is reachable from the client you connect, gated by whichever tools you've left enabled and the scope you approve.

## Add the endpoint to your client

Copy the **Endpoint** field (`/mcp` on your workspace's address) and add it to your client as a remote MCP server. There is no token to copy. In Claude Code, for example:

```bash
claude mcp add --transport http followthrough https://<your-workspace>/mcp
```

Then run `/mcp` in Claude Code and choose the server to authenticate. Other clients start the same flow when they first connect.

## Approve it in the browser

The client opens your browser at FollowThrough's consent page. If you are not signed in, you sign in first and return to the page. The page names the client:

- A client that identifies with a metadata document (Claude Code does) is shown with the host that publishes the document.
- A client that registered itself is marked as unverified, because it chose its own name. Approve it only if you just added FollowThrough to it.

Choose a scope: **Read only** restricts the client to read tools (search, list todos, read memory) and nothing else; **Full access** allows proposals and mutations too, gated the same way the in-app agent's execution mode gates them. Choose **Connect**. (**Cancel** asks you to confirm before it refuses the client.) The browser returns to the client, which receives a one-hour access token and a refresh token it renews on its own.

## What the client can do

Once connected, the client sees every tool your token and tool selection permit, each under its real name and flat input schema. Call `search_tools` to find the right tool for an intent. A read-only connection never sees proposal or mutation tools, and a full-access connection still respects your workspace tool selection.

## Disconnect a client

Open **Settings → MCP access** and choose **Disconnect** on the client's row. It takes effect at once: the next request with its access token fails with a `401`, and its refresh token stops working. To use the client again, approve it again.
