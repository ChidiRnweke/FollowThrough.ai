---
title: Agents propose, users accept
description: The trust model that decides what the agent can do on its own.
---

The agent in FollowThrough is powerful by design — it reads the project's notes, board, and memory, and it can edit them. The question the product has to answer is not *can* the agent change something, but *when may it change something without asking*.

The answer is a trust model with three tiers.

## Tier one: read freely

The agent reads the project's context — notes, todos, memory, references — without asking. Reading is side-effect free, so it is never gated. This is what lets the agent help without being re-briefed: it can see the project's state the moment a question is asked.

## Tier two: propose, and apply only with approval

Changes that alter the user's work — editing a note, creating a todo, updating project memory, inserting a diagram — are proposed as suggestions. The suggestion is reviewable: it shows what would change, where it came from (the exact selection or run), and a confidence score. The user accepts or rejects it.

This is the default posture captured in the product's guiding principle: **agents propose, the user accepts**. The controller layer enforces it structurally — the `accept`, `reject`, and `revert` operations in the suggestions, todos, memory, and diagrams controllers exist precisely so no agent change can skip the review step.

## Tier three: trust policies

Some changes are safe enough to skip the human entirely. Trust policies encode rules like *extract-promises results are auto-accepted* or *memory additions are auto-accepted*. When a proposed change matches a policy, it is applied and accepted automatically; the suggestion still exists, marked as auto-accepted, so nothing happens invisibly.

Auto-acceptance is scoped and revocable. The trust-policies controller lets the user inspect every rule and change it — and the settings surface for tool enablement keeps the guard that prevents the agent from locking itself out of its own capabilities.

## Why provenance matters

Every suggestion and every accepted change carries provenance: which selection it came from, which run proposed it, what pipeline produced it. Provenance is what makes the trust model inspectable. "The agent changed my memory" is only useful if you can trace exactly what the agent saw, proposed, and applied — and revert it if the change was wrong.

## The user remains the source of truth

The tiers are ordered by reversibility. Reading is free because it changes nothing. Proposing is the default because a wrong suggestion costs a click to reject. Auto-accepting is the exception, reserved for changes the user has explicitly decided are safe. At no point does the agent become the source of truth — the design keeps the user there.
